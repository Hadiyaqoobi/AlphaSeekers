## Critical Issues (Fix Immediately)

### CRIT-1: Homepage client-side hydration crash
- **Page:** `/en` (Homepage)
- **Severity:** 🔴 Critical
- **Description:** The homepage server-renders correctly (verified via curl — returns 98KB of fully rendered HTML), but crashes immediately during React hydration in Chrome with `TypeError: Cannot read properties of undefined (reading 'call')` in `webpack.js`. This triggers the error boundary showing "Something went wrong - An unexpected error occurred."
- **Root Cause:** A stale service worker in the browser continuously polls `/en/programs` (a non-existent route) at ~50 requests/second, which corrupts the Next.js webpack dev server's in-memory chunk cache. Once corrupted, subsequent page loads return 404 even though the initial compile succeeds.
- **Impact:** The entire cinematic landing page (Hero, Feature Tabs, Mission, AI Showcase, Footer) is invisible to users. Only the old layout chrome (white navbar with Home/Programs/How it works) remains visible above the error.
- **Console error:** `TypeError: Cannot read properties of undefined (reading 'call')` at `webpack.js`
- **Network issues:** 500 for `/favicon.ico`, constant 404 spam for `/en/programs`
- **Workaround:** Clear service workers in Chrome DevTools → Application → Service Workers → Unregister. Or use an incognito window.
- **Fix required:** Remove or update the service worker (`public/sw.js`) to not cache routes that no longer exist.

## High Priority Issues

### HIGH-1: `npm run build` hangs indefinitely during lint/type-check
- **Severity:** 🟠 High
- **Description:** `npm run build` completes webpack compilation (`✓ Compiled successfully`) but hangs forever during `Linting and checking validity of types...`. This prevents production deployments.
- **Root cause:** The ESLint plugin `@next/next` fails to load with error `(0 , _url.execOnce) is not a function`, likely due to a version mismatch between the ESLint config and the Next.js version.
- **Workaround:** Build with `--no-lint` flag: `npx next build --no-lint`
- **Impact:** Cannot deploy to Vercel/production without the workaround.

### HIGH-2: `/en/admin` and `/en/staff` return 404
- **Severity:** 🟠 High
- **Description:** The admin panel page (`/en/admin`) and staff page (`/en/staff`) return HTTP 404. These routes don't exist in the `src/app/[locale]/` directory. Admin user management is accessed at `/en/admin/users` but `/en/admin` itself has no page.
- **Impact:** Admin has no dedicated landing page. Navigation to "Admin" link goes to a 404.
- **Note:** The user approval functionality at `/en/admin/users` works correctly (verified both via API and browser).

## Medium Priority Issues

### MED-1: Registration form has no auto-save (localStorage)
- **Severity:** 🟡 Medium
- **Description:** When filling the registration form half-way and refreshing the page, all form data is lost. Per the BRD, form data should be persisted in `localStorage` to prevent data loss.
- **Impact:** Users on unstable connections (target demographic in Afghanistan) may lose their registration progress.

### MED-2: "QA Teacher Test" registered as STUDENT role despite selecting Teacher
- **Severity:** 🟡 Medium
- **Description:** In the admin pending approvals list, users who registered selecting "Teacher" are showing with role "STUDENT". The role toggle button in the registration form may not be properly updating the form state before submission.
- **Evidence:** Screenshot of admin panel showed "QA Teacher Test" with role "STUDENT" and "QA Student Test" with role "STUDENT" — both identical.
- **Impact:** Teachers cannot register correctly, requiring admin to manually change their role.
