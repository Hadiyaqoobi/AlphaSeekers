## 6. Regression found during QA — and fixed

**Symptom:** `GET /favicon.ico` returned **500 Internal Server Error** with the message:

```
Error: A conflicting public file and page file was found for path /favicon.ico
```

**Root cause:** Next.js 14 App Router's `src/app/favicon.ico` convention claims the `/favicon.ico` route automatically. When I refreshed `public/favicon.ico` with `magick` from the new icon, both files coexisted → Next.js dev rejected the route.

**Note:** `src/app/favicon.ico` (25 KB, Next.js boilerplate default) had been present since project init on Feb 8, alongside an earlier `public/favicon.ico`. The conflict was latent — never hit because neither prod nor browsers were directly fetching `/favicon.ico` during the QA windows that ran before today. My multi-res ICO update only made the latent conflict observable.

**Fix applied during QA:**

1. Replaced `src/app/favicon.ico` with the new multi-res ICO (16/32/48 px, derived from the wordmark icon).
2. Deleted `public/favicon.ico`.
3. Re-verified: `GET /favicon.ico` → 200, `image/x-icon`, 15 086 bytes ✓.

The `src/app/favicon.ico` location is the canonical place for App Router and is what every Next.js doc recommends.
